## 部署须知（改动生效需完整重启）

新配置和制度接口在后端重启后才生效。步骤：

1. 关闭 `workbench-backend`、`workbench-frontend` 两个窗口
2. `cd server && docker compose down && docker compose up -d`（重建带密码与回环绑定的容器）
3. `cd server && mvn -DskipTests package`（重新打 jar；或使用仓库自带的 `./mvnw`）
4. 双击 `start-workbench.bat`

回滚路径：`server/target/workbench-server-0.1.0.jar` 重建前请先备份；代码层面改动可按本文表格逐项回退。

## 尚未处理（P1，内容安全的根本缺口）

**全部业务数据仍在客户端 JS 中。** 22 个业务视图全部 `import` 自 `web/src/mock/data`：姓名、手机号、工资数额、党费、慰问金都编译进前端产物，任何能打开页面的人按 F12 即可看到全部数据。登录只能挡住页面的显示，挡不住数据本身。这是「内容安全管控」目前最大的缺口。

根治方案：把花名册 / 薪酬 / 请假 / 党建 / 工会 / 办公模块的数据迁移到后端 API，由后端按「角色 + 项目部」做行级过滤（`Role.dataScope` 已有 COMPANY / PROJECT 之分，`CurrentUserHolder.currentProjectId()` 可取当前项目部）。工程量较大，且需先确认两件事：

1. **部署模式**：一台共享服务器（局域网浏览器访问）还是逐机分发整包？逐机分发意味着每人都持有一份数据副本，权限隔离无从谈起，只能走共享服务器模式。
2. **数据真实化**：当前 mock 数据是否要替换为真实数据？真实数据从哪个系统导入？

其余已知风险：初始账号密码仍为弱口令（部署前必须改，或做首次登录强制改密）；JWT 无吊销机制（登出只清本地存储）；全程 HTTP 明文，局域网传输可被嗅探，共享服务器建议加重向代理上 HTTPS。
