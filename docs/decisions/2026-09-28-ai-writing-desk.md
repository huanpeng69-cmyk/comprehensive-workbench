# AI 写作台接入决策（2026-09-28）

## 背景

工作台已有依赖企业知识库检索的问答接口，但没有面向通用写作、改写任务的模型接口。写作台还需要让用户保存并复用自己的 Skill 提示词。

## 备选方案

1. 复用知识库问答接口：实现成本低，但接口语义依赖知识库检索，无法稳定承担通用写作任务。
2. 浏览器直连模型：前端集成简单，但需要把模型密钥交给浏览器，难以保护密钥。
3. 后端代理 OpenAI 兼容 Chat Completions：由后端读取服务地址、模型名和密钥，浏览器只发送本次 Skill 与写作内容。

## 决策与原因

选择方案 3。它保持供应商可替换，避免将密钥暴露到前端；新增接口不更改数据库结构，Skill 内容暂存于用户当前浏览器的 `localStorage`。调用审计只记录 Skill 名称，不记录正文。

## 运行配置

后端设置 `WORKBENCH_AI_BASE_URL`、`WORKBENCH_AI_MODEL`；云端供应商还需设置 `WORKBENCH_AI_API_KEY`。Base URL 填 OpenAI 兼容 API 根地址，例如以 `/v1` 结尾，不要将密钥写入仓库或前端配置。改好环境变量后重启后端。

## 后续约束

- 写作台不得将通用写作请求转发到知识库检索接口。
- 不在浏览器、本地存储或审计日志中保存模型 API 密钥或用户正文。
- 如果以后需要跨设备共享 Skill，再另行评估服务端持久化和权限模型。
