# AI 模型配置「可编辑」判定归属决策（2026-10-09）

## 背景

AI 写作台的模型配置谁能改，原先由前端硬编码角色表（`CONFIG_EDIT_ROLES = ['SYSTEM_ADMIN','HR_ADMIN']`）与后端 `@PreAuthorize` 两处各自维护。两边口径一旦漂移，就会出现「按钮看得见、保存被 403」或「后端放行、按钮消失」的错位。

## 备选方案

1. 继续两处维护，靠注释互相提醒保持一致。
2. 后端在 `AiConfigView` 增加 `editable` 字段，由 `AiConfigService.view()` 按当前登录用户角色计算并返回；前端只读该字段渲染 UI，删除自己的角色副本。

## 决策与原因

选方案 2。后端本来就是权限的执行者（`@PreAuthorize`），让它同时是权限的「宣告者」，UI 与实际权限天然一致；后端将来放开新角色时前端零改动。字段计算放在 service 的 `view()` 里，GET 与 PUT 两个入口自动共享同一口径。

## 约束

- 前端**不得**再引入任何「按角色判断 UI 能力」的硬编码列表；一律以后端返回的能力字段为准。
- 后端新增/调整可编辑角色时，只需同步修改 `CONFIG_EDITABLE_ROLES` 与对应 `@PreAuthorize`（两处都在后端、距离很近）。
