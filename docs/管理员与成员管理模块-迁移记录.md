# 管理员账号与成员管理模块 · 迁移记录

> 日期：2026-09-23 ｜ 关联需求：创建管理员账号，拥有自行添加/修改/删除其他成员（系统登录账号）的权限。
> 范围：后端身份模块（identity）+ 前端「成员管理」页面。已通过 `mvn compile` 与 `vue-tsc --noEmit && vite build` 验证。

## 1. 背景与范围
- **"成员" = 系统登录账号 `sys_user`**（identity 模块的 `User` 实体，既作登录账号也作人员载体），**不是** `StaffList.vue` 里那套 mock 驱动的 HR「人员花名册」。
- 目标：① 产出一个真正具备 `SYSTEM_ADMIN` 角色的管理员账号；② 让该账号能在界面上自助**增 / 改 / 删 / 重置密码**其他成员。
- 已有 `SYSTEM_ADMIN` 角色定义（`DataInitializer` 中），但**从未分配给任何用户**；且 `DataInitializer` 仅在表为空时播种，当前库已有数据，故普通播种逻辑不会再创建管理员。

## 3. 设计决策
- **管理员账号通过 `DataInitializer.ensureAdminAccount()` 落地，而非新建独立 `CommandLineRunner`**：因为 `CommandLineRunner` 的排序若早于 `DataInitializer`，在空库场景下会先建出 admin → 触发 `count()>0` → demo 数据不再播种，导致库残缺。放进同一个 runner、在 demo 播种之后执行，可彻底规避排序竞态，且天然幂等（已存在则跳过）。
- **鉴权用 `@PreAuthorize("hasRole('SYSTEM_ADMIN')")`**：`SecurityConfig` 已开启 `@EnableMethodSecurity`；JWT 过滤器把角色码写成 `ROLE_<code>` 权威，与 `hasRole` 的语义一致。所有 `/api/users` 端点受此把关，非管理员直接 403。
- **`UserResponse` 不含 `passwordHash`**：杜绝密码哈希外泄。
- **创建成员默认口令 `User@2026`**（留空时）；管理员初始口令 `Admin@2026`（文档可查，登录后可改）。
- **删除防呆**：① 不能删除当前登录账号；② 若删除会导致「启用中的管理员」归零，则拒绝（避免锁死系统）。
- **角色赋值走角色码**：前端下拉来自 `GET /api/users/roles`，后端 `resolveRoles` 按码查 `sys_role`，未知码静默丢弃。

- 路由 `beforeEach` 仅校验 `token`，未做角色级路由守卫；非管理员手动输入 URL 可进入页面但 API 会 403。后续若需更强收敛，可加角色守卫（当前菜单已隐藏，风险可控）。
- 本沙箱无法连 Postgres，未做端到端运行验证，仅做编译/构建级验证。
