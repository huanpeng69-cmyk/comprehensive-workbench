# 侧边栏折痕：根因与防再犯检查

> 记录日期：2026-11-06
> 关联代码：`web/src/layouts/MainLayout.vue`（`.nav-item`）、`web/src/styles/glass.css`（`.wb-sidebar`）
> 性质：缺陷根因记录（AGENTS.md 第 8 条），不是设计效果

## 1. 现象

鼠标移入左侧玻璃侧边栏的菜单项时，侧边栏**右缘出现一条 1px 竖直亮线**（俗称"折痕"），
鼠标移出后消失。现象与具体页面无关（任意路由下悬停菜单项都能看到），与滚动位置相关。

## 2. 取证（像素级）

在 1440×900 视口、登录后 `/hr/staff` 页面取样：

| 量 | 数值 |
| --- | --- |
| 亮线 x 坐标 | 299（侧边栏右缘） |
| 正常帧该列亮度 | 约 185 |
| 异常帧该列亮度 | 200–203 |
| 左侧相邻列亮度 | 143 |
| 右侧相邻列亮度 | 104 |
| 阶跃宽度 | 1px |

即异常时该列亮度被抬高约 15–18，颜色接近卡片填充（203）而非描边渐变，
说明它**不是边框被加粗，而是玻璃卡片的填充被合成到了描边位置**。

复现前提：页面必须产生了文档级滚动（`documentElement` 可滚动），
这样 `position: sticky` 的侧边栏才会进入 sticky 状态并被单独提升为合成层。
不滚动时（首屏内容不足）无法复现。

## 3. 根因

三个条件同时成立时才会出现：

1. **玻璃容器用 `backdrop-filter` + 半透明描边**（`glass.css` 的 `.wb-sidebar`）——
   背景模糊需要在合成阶段采样，容器被固定提升为一个合成层，其描边（border/outline 的渐变边）
   在合成时与填充分开处理。
2. **悬停时子元素改变图层树**：`.nav-item:hover { transform: translateX(2px) }` 且带
   `transition: transform 0.16s`。`transform` 从 `none` 变为非 `none` 会让该子元素在过渡期间
   获得自己的合成层，过渡结束时又失去——动画中画面被反复重绘。
3. **`position: sticky` 的侧边栏**在该过程中重新计算 clip，右缘 1px 的描边与填充错位一帧。

结论：这是**悬停过渡触发图层树变化 → 玻璃容器重新合成 → 描边与填充错层**的瞬态合成缺陷，
不是 CSS 写错颜色。因此不能靠调整 border 颜色/宽度解决。

## 4. 修复

按最小改动原则，只给 `.nav-item` 声明并发提示，让它**始终**是合成层，
消除"过渡期间获得/失去合成层"的图层树抖动（`MainLayout.vue:314-318`）：

```css
.nav-item {
  /* 悬停位移会改变图层树，玻璃容器（backdrop-filter）重新合成时描边与填充错层，
     侧边栏右缘会出现 1px 亮线。提前声明 will-change 让该元素常驻合成层。 */
  will-change: transform;
}
```

未采用的备选：

- **B1** 给 `.wb-sidebar` 加 `will-change: transform`：同样能消除抖动，但把整个侧边栏常驻合成层，
  显存占用远大于单个菜单项。
- **B2** 删除 `translateX(2px)`：彻底没有图层变化，但丢掉了既有交互反馈，属行为变更。
- **B3** 描边由 `border` 改 `box-shadow: inset`：回避合成错层，但会改动玻璃质感的具体渲染，
  影响所有玻璃容器，超出本次范围。

## 5. 防再犯检查（回归检查点）

改动侧边栏、玻璃容器或任意导航项样式后，逐项确认：

1. 页面滚动到出现滚动条后，鼠标**连续移入/移出**左侧菜单项各 5 次，
   侧边栏右缘**不得出现 1px 亮线**（判据：该列亮度应稳定在 185±3，不得出现 200 以上）。
2. 不要在 `backdrop-filter` 玻璃容器**内部**的子元素上，对 `transform` / `opacity` / `filter`
   做"从无到有"的过渡——需要动画时给该元素常驻 `will-change`，或改用不产生新图层的属性
   （如 `margin`、`padding`、`background-position`）。
3. 代码评审时，`grep -n "will-change" web/src` 应能解释每一处为什么需要——
   它是性能提示而非装饰，滥用会占用显存。
4. `will-change` 只加在会动画的元素上，不要加在容器根节点（见备选 B1 的代价）。

## 6. 验证状态（如实记录）

- 已确认：`will-change: transform` 在构建产物与运行页面的 `getComputedStyle` 中生效；
  `.nav-item:hover { transform: translateX(2px) }` 与 0.16s 过渡保持不变（交互反馈未丢）。
- 已确认：构建产物 CSS 中 `.nav-item` 规则包含 `will-change:transform`。
- **未完成**：修复前后的像素级 A/B 对比。本次会话中内置浏览器截图通道反复超时，
  无法在"悬停态"稳定取帧，因此 185 vs 200–203 的判据**没有在修复后复测**。
  结论的正确性依据是根因分析（图层树抖动），而非修复后的像素回归证据。
  肉眼确认仍需人工执行第 5 节第 1 条。
